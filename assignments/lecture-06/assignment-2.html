Assignment — The Safe Calculator

Build a calculator that never crashes, whatever the user types.

Easy–MediumAbout 30 minJava
01

The scenario

You are building a tiny calculator for a school fair stall. Visitors type things like 10 / 2, but people make mistakes: they divide by zero, type words instead of numbers, or forget half the sum. Your calculator must never crash. It should politely say what went wrong instead.

try / catchmultiple catch blocksArithmeticExceptionNumberFormatExceptionArrayIndexOutOfBoundsException
02

Your task

Each calculation arrives as a String[] with three parts: first number, operator, second number. Complete calculate so that:

  1. It converts the first and third parts to int and applies the operator (+ - * /).
  2. A good calculation prints like 10 / 2 = 5.
  3. NumberFormatException (text instead of a number) prints Please enter whole numbers only.
  4. ArithmeticException (divide by zero) prints Cannot divide by zero.
  5. ArrayIndexOutOfBoundsException (missing parts) prints Expected: number operator number.

04

Stuck?

Everything risky (parsing, reading parts[...], dividing) goes inside one try block. The three catch blocks sit one after another below it.

Compare strings with op.equals("+"), not ==. An if / else if / else chain works well.

InputWhat throws
"ten"Integer.parseInt → NumberFormatException
10 / 0ArithmeticException
only 2 partsparts[2] → ArrayIndexOutOfBoundsException
05

Solution

Main.java
class Main {
    static void calculate(String[] parts) {
        try {
            int a = Integer.parseInt(parts[0]);
            String op = parts[1];
            int b = Integer.parseInt(parts[2]);
            int result;
            if (op.equals("+")) {
                result = a + b;
            } else if (op.equals("-")) {
                result = a - b;
            } else if (op.equals("*")) {
                result = a * b;
            } else {
                result = a / b;
            }
            System.out.println(a + " " + op + " " + b + " = " + result);
        } catch (NumberFormatException e) {
            System.out.println("Please enter whole numbers only");
        } catch (ArithmeticException e) {
            System.out.println("Cannot divide by zero");
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("Expected: number operator number");
        }
    }

    public static void main(String[] args) {
        calculate(new String[]{"10", "/", "2"});
        calculate(new String[]{"10", "/", "0"});
        calculate(new String[]{"ten", "+", "5"});
        calculate(new String[]{"7", "*"});
    }
}

Notice that for {"7", "*"} the first parseInt works, but reading parts[2] throws, so the third catch runs. Java picks the first catch block whose type matches.

06

Stretch challenge

Add a fourth catch block, catch (Exception e), that prints Something unexpected happened. Where must it go, and what happens if you put it first? (Try it, then re-read the catch-order mistake in the chapter.)

It must go last. Exception is more general than the other three, so if it came first the compiler would report that the later catch blocks can never be reached.
