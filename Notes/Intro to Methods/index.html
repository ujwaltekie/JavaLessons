Chapter — Methods

Naming a task so you can ask for it by name, again and again.

A method is a named block of Java code that performs a particular task.

Think of it like a recipe in a cookbook — write the instructions once, then use the recipe's name whenever you need that dish again. This chapter builds up everything you need to read, write, and call a method with confidence.

01

What is a method?

A method is a block of code designed to perform a specific task. Suppose a program needs to greet the user several times — instead of repeating the greeting code, we put it inside a method.

Greet.java
void greet() {
    System.out.println("Hello!");
}

Whenever we want to perform the greeting task, we call the method:

Java
greet();
Analogy — the "Print" button

You don't need to know the internal instructions required to print a document. You simply press the button. The method name tells Java what task you want; the code inside defines how it's done.

02

Why do we use methods?

Methods let us organise code into smaller pieces, reuse code instead of repeating it, and give meaningful names to tasks — which makes programs easier to read, test, and debug.

Without a method

Java
System.out.println("Welcome to Java!");
System.out.println("Welcome to Java!");
System.out.println("Welcome to Java!");

With a method

Java
void welcome() {
    System.out.println("Welcome to Java!");
}

welcome();
welcome();
welcome();
Think of it this way

Method = give a name to a task. Once a task has a name, you can ask Java to perform it by calling its name.

04

What does void mean?

This method performs a task but does not send a value back to the place where it was called.

Java
void displayMessage() {
    System.out.println("Java is fun!");
}
Analogy — a vending machine

Pressing a button makes the machine turn on its light. It performs an action, but you don't receive a separate value back. A void method is the same: perform an action, but don't return a value.

05

Method name

The method name identifies the task the method performs. A good name describes what the method does.

Good names

printReport() calculateAverage() displayMenu()

Poor names

abc() doSomething()
Tip

Compare calculateBill(); with doIt(); — the first immediately communicates purpose.

06

Method body

The method body is the section between { and } — the instructions the method performs.

Java
void greetStudent() {
    System.out.println("Welcome!");
    System.out.println("Let's learn Java.");
}
Analogy — a recipe

Recipe name: MakeTea. Instructions: boil water, add tea, add milk, add sugar, serve.

Java
void makeTea() {
    boilWater();
    addTea();
    addMilk();
    addSugar();
}

The method name is the recipe name. The method body is the instructions.

07

Method header

The method header is everything before the method body — it tells you the return type, name, and parameters.

void greet(String name) ← Method Header { System.out.println("Hello!"); } ← Method Body
Remember

Header = information about the method. Body = instructions performed by the method.

08

Method signature

The method signature identifies a method by its name and the number, type, and order of its parameters. void is not part of the signature.

Method header

void greet(String name)

Method signature

greet(String)
Method headerMethod signature
Includes return typeDoes not include return type
Includes parameter namesParameter types are used

Common mistake

Students often write void add(int, int) as the signature — wrong, because the return type isn't included. Correct: add(int, int).

09

Parameters

Sometimes a method needs information to do its task — a method that greets a particular person needs to know their name. We give it that information through a parameter.

Java
void greet(String name) {
    System.out.println("Hello " + name);
}

greet("Anu");
greet("Rahul");
greet("Priya");
Output: Hello Anu Hello Rahul Hello Priya

Why do we need parameters?

Without them, we'd need a separate method for every person:

Java
void greetAnu() { System.out.println("Hello Anu"); }
void greetRahul() { System.out.println("Hello Rahul"); }
Analogy — a parcel delivery address

A delivery service uses one process for every parcel — it just receives a different address each time. One method can receive different information through parameters.

10

Formal vs. actual parameters

A formal parameter is the placeholder written in the method declaration. An actual parameter (or argument) is the real value supplied when the method is called.

METHOD DECLARATION void greet(String name) ↑ Formal parameter (placeholder) METHOD CALL greet("Anu"); ↑ Actual parameter (value supplied)
Formal parameterActual parameter
Written in method declarationWritten in method call
Acts as a placeholderProvides the actual value
String name"Anu"
Receives informationSupplies information
Memory trick

Formal = form/template ("what kind of information do I expect?") · Actual = actual value ("here is the actual information.")

11

Multiple parameters, order, and types

A method can accept more than one parameter. Values are matched to parameters by position, not by name — and they aren't restricted to one data type.

Java
void introduce(String name, int age) {
    System.out.println("Name: " + name);
    System.out.println("Age: " + age);
}

introduce("Anu", 20);
introduce("Anu", 20) │ │ ↓ ↓ name age
Mixed types
void displayDetails(String name, int age, double height) {
    System.out.println(name);
    System.out.println(age);
    System.out.println(height);
}

displayDetails("Anu", 20, 165.5);
Remember

Parameters are matched in order. displayStudent(20, "Anu") is wrong when the method expects (String name, int age) — the order and types don't match.

12

Zero, one, or many parameters

A method doesn't always need outside information.

No parameters
void showWelcomeMessage() {
    System.out.println("Welcome to Java!");
}
showWelcomeMessage();
Analogy — a pre-programmed alarm clock

You press a button and it performs its predefined task — it doesn't need extra information every time.

Multiple parameters
void displaySum(int number1, int number2) {
    System.out.println(number1 + number2);
}
displaySum(10, 20);   // → 30

A complete example

Java
void displayStudent(String name, int age) {
    System.out.println("Student: " + name);
    System.out.println("Age: " + age);
}

displayStudent("Anu", 20);

13

How a method call works

Java connects the supplied value to the parameter — during the call, name represents "Anu", so the method effectively performs:

Java
System.out.println("Hello " + "Anu");   // → Hello Anu

One major advantage of methods is reuse — write the task once and use it many times:

Java
greet("Anu");
greet("Rahul");
greet("Priya");
greet("Arun");
14

void with parameters, and method vs. call

A method can combine a void return type with parameters — it does something, but doesn't return a value.

Java
void printSquare(int number) {
    System.out.println(number * number);
}
printSquare(5);   // → 25

Method vs. method call

Defining a method creates it. Calling a method asks Java to execute it — writing the recipe is not the same as making the tea.

Definition

void makeTea() { ... }

Call

makeTea();

A method can call another method

Java
void startProgram() {
    showWelcome();
}

void showWelcome() {
    System.out.println("Welcome!");
}
Analogy — a restaurant

A restaurant doesn't have one giant task called "RunRestaurant." Instead: takeOrder(), prepareFood(), serveFood(), collectPayment() — each method handles one responsibility.

15

Good method design

A method should ideally perform one clear task.

Focused

void printStudentName(String name) { System.out.println(name); }

Unfocused

void doEverything(...) { // name, marks, reports, // menu, payment... }
Tip — one method, one main job

This makes programs easier to understand, maintain, and debug.

One complete mental model

Whenever you see a Java method, ask: What is it called? What does it return? What information does it need? What does it actually do? What is supplied when it's called?

METHOD │ ┌───────────┴───────────┐ │ │ HEADER BODY │ │ ┌───┼────┐ Instructions │ │ │ void name parameters │ └───────┐ │ Method Call │ greet("Anu") │ ↓ "Anu" Actual Parameter
⭐ One-line summary

A Java method is a named, reusable block of code that performs a specific task; parameters allow us to provide information to that task, while a void method performs its task without returning a value.
