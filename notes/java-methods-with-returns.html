Methods with Returns

Methods that don't just act — they hand something back.

A method can calculate or produce a value and send that value back to the code that called it.

Think of it like ordering from a vending machine: you make a request, the method performs work, produces a value, and that value comes back to you. In int result = add(10, 20); the method calculates 30, and that 30 comes back and is stored in result.

You make a request ↓ Method performs work ↓ Method produces a value ↓ Value comes back to you
01

What is a return type?

A return type tells us what kind of value a method sends back after it finishes its work.

Java
int add(int a, int b) {
    return a + b;
}

Here, int is the return type. It tells Java: "This method will send an int value back."

02

void vs. a returning method

You've already seen methods like this, which display a result but don't give it back:

Java
void displaySum(int a, int b) {
    System.out.println(a + b);
}

Compare it with a method that returns the result instead:

Java
int calculateSum(int a, int b) {
    return a + b;
}
void methodReturning method
Performs a taskPerforms a task and produces a value
Does not return a valueReturns a value
Uses voidUses a data type such as int, double, String
void display()int calculate()
Analogy — two calculators

Calculator A: you enter 10 + 20, it displays 30 — but gives you nothing else to use. Calculator B: it produces 30 and lets you take that value and use it elsewhere. A returning method is like Calculator B.

04

The return keyword

The return keyword sends a value back from a method.

Java
int getNumber() {
    return 10;
}

Think of return 10; as saying: "Here is the result. Send it back."

Saving the returned value in a variable

A returned value can be stored in a variable, then used like any other:

Java
int getNumber() {
    return 100;
}

int number = getNumber();

System.out.println(number);   // → 100
Key idea

A returned value can be stored, displayed, compared, calculated with, or passed somewhere else.

05

Return type and returned value must match

The type after return must be compatible with the declared return type.

Java
int getAge() {
    return 20;          // int → int ✓
}

double getPrice() {
    return 499.99;      // double → double ✓
}

String getName() {
    return "Anu";       // String → String ✓
}
Common mistake

Don't promise one type and return an incompatible value:

Won't compile
int getNumber() {
    return "Hello";   // int promised, String returned
}
06

Calling a returning method from main()

A common place to call methods is main().

Calculator.java
class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    public static void main(String[] args) {
        int result = add(10, 20);
        System.out.println(result);   // → 30
    }
}

The flow behind int result = add(10, 20);:

main() │ calls ↓ add(10, 20) │ ↓ a=10, b=20 │ ↓ a + b = 30 │ ↓ return 30 │ ↓ main() receives 30 │ ↓ result = 30
Note

This chapter focuses on returning methods — the mechanics of static and access modifiers aren't the focus here.

07

Returning a calculation — and why not just print it?

Java
int square(int number) {
    return number * number;
}

int result = square(5);   // → 25

Compare a method that prints with one that returns:

Prints

void square(int number) { System.out.println( number * number); }

Returns

int square(int number) { return number * number; }

With the returning version, the value is available for further use:

Java
int result = square(5);
int finalValue = result + 10;
System.out.println(finalValue);   // → 35
Important

Printing a value and returning a value are not the same thing. System.out.println() sends information to the screen. return sends information back to the code that called the method.

08

Analogy: a coffee machine ☕

You select Coffee. The machine receives the request, prepares coffee, produces coffee, and gives it to you.

Java
String makeCoffee() {
    return "Coffee";
}

String drink = makeCoffee();   // drink = "Coffee"

The method is like the machine, and the returned value is like the coffee.

09

Returning different data types

A method doesn't always have to return an int — the general pattern dataType methodName() { return value; } works for any type.

Java
int getAge() {
    return 20;
}

double getPrice() {
    return 499.99;
}

String getGreeting() {
    return "Welcome to Java!";
}

boolean isEven(int number) {
    return number % 2 == 0;
}

A boolean-returning method is often used directly in a decision:

Java
boolean result = isEven(10);   // → true

if (result) {
    System.out.println("The number is even.");
}

And a double can carry a calculated measurement:

Java
double calculateArea(double radius) {
    return 3.14 * radius * radius;
}

double area = calculateArea(5);   // → 78.5
10

Parameters go in, return values come out

Parameters give information into the method. return sends information out of the method.

Java
int multiply(int number1, int number2) {
    return number1 * number2;
}

int result = multiply(6, 7);   // → 42
INPUT ↓ 6 7 \ / \ / multiply() │ ↓ 42 │ OUTPUT
Memory trick

Think of a method as a machine: INPUT → [ METHOD ] → OUTPUT. Parameters are the input. The returned value is the output.

11

Using a returned value

You don't always have to store the returned value — you can print it directly, use it in another expression, or feed it straight into another method.

Calling a method directly

Java
int add(int a, int b) {
    return a + b;
}

System.out.println(add(10, 20));   // → 30

Using it in another calculation

Java
int result = square(5) + 10;   // 25 + 10 → 35

Feeding one returning method into another

Java
int result = addTen(square(5));
// square(5) → 25
// addTen(25) → 35
Analogy — an assembly line

Machine 1 → Machine 2 → Machine 3. Each machine produces something that becomes the input for the next. Returning methods can work the same way.

12

Storing and reusing results

Storing a returned value in a variable is one of the most common patterns — the variable is simply a place we choose to keep the value.

Java
int calculateTotal(int price, int quantity) {
    return price * quantity;
}

int total = calculateTotal(500, 3);   // total = 1500

System.out.println("Total: " + total);

The same method can be reused with different inputs, into different variables:

Java
int firstResult  = add(10, 20);   // 30
int secondResult = add(50, 25);   // 75

A returned value can also feed a further calculation, such as an average built from a total:

Java
int total = calculateTotal(80, 90, 85);
double average = total / 3.0;
13

return ends the method — and must produce a value

When Java reaches a return statement, the method finishes immediately. Anything written after it is unreachable.

Java
int getNumber() {
    return 10;
    // unreachable — the method already ended
}

And if a method's return type isn't void, it must return an appropriate value on every valid path:

Correct

int getNumber() { return 10; }

Incorrect

int getNumber() { System.out.println("Hi"); // no return! }

The value after return can be any expression — Java evaluates it and sends the result back:

Java
int doubleNumber(int number) {
    return number * 2;
}

int findDifference(int a, int b) {
    return a - b;
}
14

Complete walkthrough with main()

Calculator.java
class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    public static void main(String[] args) {
        int result = add(15, 25);
        System.out.println("Result: " + result);
    }
}
Output: Result: 40
StepWhat happens
1Method is defined: int add(int a, int b) { return a + b; }
2Method is called: add(15, 25)
3Parameters receive values: a = 15, b = 25
4Calculation occurs: 15 + 25 = 40
5Method returns the value: return 40
6main() stores it: int result = 40;
7Result is displayed: System.out.println(result);
15

One method, many results

A method doesn't have one permanent answer — the result depends on the input.

Java
int square(int number) {
    return number * number;
}

int a = square(2);    // 4
int b = square(5);    // 25
int c = square(10);   // 100
Analogy — a juice machine

Put in an orange → orange juice. Put in an apple → apple juice. Same method + different parameters = potentially different returned values.

Booleans for decisions, strings for display

Java
boolean isEligible(int age) {
    return age >= 18;
}

String createMessage(String name) {
    return "Welcome, " + name;
}

The method doesn't need to print anything — it just answers a question, or prepares text, and lets the caller decide what to do with the result. That's what gives a returning method flexibility:

Java
int total = calculateTotal(500, 2);

System.out.println(total);
int discountedTotal = total - 100;
if (total > 500) {
    System.out.println("Large order");
}
Key advantage

A method that returns a value can be used as a building block for other calculations and decisions.

Return type

The kind of value a method promises to send back. int, double, String…

return

The keyword that sends a value back and ends the method immediately.

What actually comes back — e.g. 30 from return a + b;

Using it directly

System.out.println(add(10, 20)); — no variable needed.

Chaining

addTen(square(5)) — one method's output becomes another's input.

Final mental model

PARAMETERS ↓ ┌────────────────┐ │ METHOD │ │ processing │ └───────┬─────────┘ │ return │ ↓ RETURNED VALUE │ ┌────────┴────────┐ ↓ ↓ Store it Use it directly in variable in an expression
⭐ The golden rule

Parameters bring information INTO a method. return sends a value OUT of a method.

For int result = add(10, 20); the journey is: 10, 20 → parameters → add() → 10 + 20 → return 30 → result = 30.
