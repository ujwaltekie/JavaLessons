Chapter — Parameter Passing, Access Modifiers, static, and Variables

What belongs to an object, what belongs to the class, who can see it, and what happens to data when a method gets hold of it.

Several ideas that are often confusing on their own turn out to be one connected story.

How data enters a method, how that method can (or can't) change it, who's allowed to touch a class member, whether something belongs to an object or the whole class, and where a variable is even visible — it's all one picture once you see the connections.

How data enters methods ↓ Pass by value / reference ↓ Pure vs. impure methods ↓ Access modifiers — who can see it? ↓ Instance vs. static — object or class? ↓ Instance vs. local — where does it live?

Part 1 — Pass by value

01

What does "pass by value" mean?

Pass by value means a method receives a copy of the value — not the original.

Java
void changeNumber(int number) {
    number = 100;
}

int x = 10;
changeNumber(x);
System.out.println(x);   // → 10, not 100

x stays 10 because the method only ever touched its own copy, called number.

Analogy — a photocopy 📄

The original document reads 10. Someone asks for a photocopy; you hand over a copy. They write 100 on the copy. Did the original change? No. That's pass by value.

02

Java is strictly pass-by-value

⭐ Key fact

Java is strictly pass-by-value — for both primitives (int, double, char, boolean…) and object references. Java never does true pass-by-reference.

Java
void increase(int number) {
    number = number + 1;
}

int count = 5;
increase(count);
System.out.println(count);   // → 5

Inside the method, number becomes 6 — but count outside never changes.

03

What about objects?

Here's where students often get confused.

Java
class Student {
    String name;
}

void changeName(Student student) {
    student.name = "Rahul";
}

Student s = new Student();
s.name = "Anu";
changeName(s);
System.out.println(s.name);   // → Rahul

This looks like pass-by-reference — the change is visible outside! But Java is still pass by value. What gets copied is the reference to the object, not the object itself.

04

What is an object reference?

Student s = new Student(); — the variable s doesn't literally hold the object. It holds a reference that lets Java reach the object.

s ───reference───→ ┌───────────────┐ │ Student │ │ name = "Anu" │ └───────────────┘

When we call changeName(s), Java copies that reference — so both s and the parameter student point at the same object:

s ───────┐ ↓ Object ↑ student ─┘
Analogy — a house address 🏠

s is like "House at 123 Main Street." The method receives a copy of that address — both know how to reach the same house. If the method rearranges the furniture inside, you'll see that through s too, because it's the same house.

05

The crucial difference: changing the object vs. changing the reference

Two very different things can happen inside a method that receives an object.

Changing the object

student.name = "Rahul";

Changing the reference

student = new Student();
Changes the object → visible outside
void changeName(Student student) {
    student.name = "Rahul";
}
// s.name becomes "Rahul"
Changes the reference → NOT visible outside
void changeStudent(Student student) {
    student = new Student();
    student.name = "Rahul";
}
// s.name is still "Anu"

In the second case, student = new Student(); only redirects the local copy of the reference to a brand-new object. s back in the caller still points to the original:

s → Object A (name = "Anu") student → Object B (name = "Rahul") ← only the local copy moved
06

What is passed?A copy of the valueAlias to the original variable

🚨 Exam alert

If asked "does Java use pass by value or pass by reference?" — the answer is always pass by value. For objects, the value being passed is a reference to the object.

Part 2 — Pure and impure methods

07

Pure methods

A pure method (1) produces the same output for the same input, and (2) doesn't change external state or cause observable side effects.

Java
int square(int number) {
    return number * number;
}

double calculateArea(double radius) {
    return 3.14 * radius * radius;
}
Analogy — a calculator 🧮

Enter 10 + 20, get 30 — every time. The calculator doesn't secretly change your bank account or calendar.

Why pure methods are nice

They're easier to understand, test, and debug, more predictable, and easier to reuse — same input always gives the same result, with nothing hidden.

08

Impure methods

An impure method has one or more side effects, or depends on changing external state.

Java
int count = 0;

void increaseCount() {
    count++;
}

void displayMessage() {
    System.out.println("Hello");   // side effect: console output
}
Analogy — a bank deposit 🏦

void deposit(double amount) { balance = balance + amount; } doesn't just calculate a result — it changes the account's actual state. That's impure.

📌 Important

"Impure" doesn't mean bad. Programs need side effects to display information, save files, update objects, and change state — impure methods are often necessary.

09

Pure vs. impure, side by side

Pure methodImpure method

Pure = predictable. Impure = interactive — useful whenever the program needs to do something to the world or change state.

Part 3 — Access modifiers

10

Access modifiers

Access modifiers control where a class, method, constructor, or variable can be accessed from. Java has four levels: public, protected, default (none written), and private.

Analogy — office building security 🏢

public is the open reception area. protected is a restricted area for employees and related people. default is available only within one department. private is a personal locker only its owner can open.

More accessible ↓ public ↓ protected ↓ default ↓ private ↓ More restricted
11

public and private

public — open to everyone
class Student {
    public String name;
    public void displayName() { System.out.println(name); }
}

Student student = new Student();
student.name = "Anu";           // OK from outside
private — my personal locker
class BankAccount {
    private double balance;

    void deposit(double amount) {
        balance = balance + amount;   // OK — inside the class
    }
}

account.balance = 5000;   // NOT allowed — balance is private
Why use private? Encapsulation

Instead of letting outside code do account.balance = -100000; directly, we control the change through a method: if (amount > 0) balance = balance + amount; — the class stays in charge of its own data.

12

protected and default access

protected
class Animal {
    protected String name;
}

class Dog extends Animal {
    void showName() {
        System.out.println(name);   // OK — subclass access
    }
}

protected gives access within the same package, plus subclasses (including subclasses in other packages) — more restricted than public, more open than private.

default (nothing written)
class Student {
    String name;   // no modifier → default/package-private

    void displayName() {
        System.out.println(name);
    }
}

Default access is visible to classes in the same package only.

13

Access modifier comparison

Access levelSame classSame packageSubclass, other packageOther package
public✅✅✅✅
protected✅✅✅*❌

* Through the subclass relationship, subject to Java's inheritance access rules.

Simplest memory order

public → everywhere · protected → package + subclasses · default → package · private → class only.

Part 4 — static

14

What is static?

static means a member belongs to the class rather than to each individual object. Without it, an instance variable belongs to one object; with it, there's a single class-level member shared by everyone.

Java
class Student {
    String name;                          // instance
    static String schoolName = "ABC School"; // static
}

Student student1 = new Student();
Student student2 = new Student();
student1.name = "Anu";
student2.name = "Rahul";
student1
name = Anu
student2
name = Rahul
Student.schoolName
shared = "ABC School"
Analogy — a school 🏫

Every student has their own name, age, roll number — like instance variables. But schoolName is the same for all 500 students — a static variable belonging to the class as a whole.

15

Static methods

Java
class MathTools {
    static int square(int number) {
        return number * number;
    }
}

int result = MathTools.square(5);   // → 25, called via the class

Instance method

student.display();

Static method

MathTools.square(5);

There's no need to create a new MathTools object just to perform a general calculation — that's exactly what static is for.

16

A static method can't automatically reach instance data

Problem
class Student {
    String name;

    static void display() {
        System.out.println(name);   // won't compile — WHOSE name?
    }
}

A static method has no particular object attached to it, so it can't reach name — which student's name would it even mean?

Fix — give it an object
static void display(Student student) {
    System.out.println(student.name);
}

Student.display(student);
17

Static vs. instance

InstanceStatic
Belongs to an objectBelongs to the class
Each object has its own copyOne member shared by all objects
Usually accessed through an objectUsually accessed through the class name
student.nameStudent.schoolName
Counter — the classic demonstration
class Counter {
    static int count = 0;
    Counter() { count++; }
}

Counter c1 = new Counter();
Counter c2 = new Counter();
Counter c3 = new Counter();
System.out.println(Counter.count);   // → 3, one shared variable

Change count to a plain instance variable instead, and each object ends up with its own count = 1 — no sharing at all.

Part 5 — Instance and local variables

18

Instance variables vs. local variables

Java
class Student {
    String name;             // instance — belongs to each object

    void display() {
        String message = "Hello";   // local — temporary
        System.out.println(message);
    }
}
Analogy — a student's backpack 🎒

Instance variables are things that belong to the student long-term: name, age, roll number. Local variables are things used briefly for one task — a temporary number you're calculating, then forget.

Instance variableLocal variable
Declared inside class, outside methodsDeclared inside a method/constructor/block
Belongs to the objectBelongs to that execution only
Gets a default value automaticallyMust be assigned before it's read
Usable across the object's instance methodsAccessible only within its own scope
19

Default values — instance vs. local

Instance variables automatically get a default value if you don't set one:

int → 0 double → 0.0 boolean → false String → null
⚠️ Important — this does NOT apply to local variables

void display() { int age; System.out.println(age); } won't compile — a local variable must be definitely assigned before it's read. Fix: int age = 20;

Part 6 — Putting it all together

20

Static, instance, and local — together

Java
class Student {
    String name;                     // Instance — belongs to each object

    static String school = "ABC";    // Static   — belongs to the class

    void display() {
        int age = 20;                // Local    — belongs to this call only
        System.out.println(name);
        System.out.println(school);
        System.out.println(age);
    }
}
The three-level school analogy 🏫

Class-level: the school name — shared by everyone → static. Student-level: each student's name and roll number — different per student → instance. Temporary classroom work: a total or average calculated on the spot → local.

22

The most important exam traps

  • ✕ "Java passes objects by reference." — No. Java is pass-by-value; for objects, the value copied is the reference.
  • ✕ "A private variable can be accessed by any class in the same package." — No. Private restricts direct access to the declaring class only.
  • ✕ "static means the variable can't change." — No. static means it belongs to the class, not that it's constant.
  • ✕ "Instance variables must be manually initialised." — Not necessarily; they get default values automatically.
  • ✕ "Local variables automatically get default values." — No. They must be definitely assigned before use.
  • ✕ "Impure methods are bad methods." — No. Programs need side effects to be useful.

Final challenge Pass by value, three steps deep
Java
class Box { int value; }

void change(Box box) {
    box.value = 50;
    box = new Box();
    box.value = 100;
}

Box b = new Box();
b.value = 10;
change(b);
System.out.println(b.value);

50. First box.value = 50; changes the shared object (visible via b). Then box = new Box(); redirects only the local box reference — box.value = 100; after that touches the new object, not the one b points to.
