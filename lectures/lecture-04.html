Chapter — Method Overloading & Constructor Overloading

One name, many forms — letting Java pick the right version for you.

Overloading means having multiple methods or constructors with the same name, but different parameter lists.

Think of a person named Alex who can respond to different requests: Alex("Hello"), Alex("Hello", "Rahul"), Alex("Hello", "Rahul", 20). The name is the same, but the information supplied is different — and Java uses the parameters to determine which version should run.

You call a method/constructor by name ↓ Java looks at the arguments you supplied ↓ Java matches them to a parameter list ↓ That specific version runs
01

What is method overloading?

Method overloading happens when a class has two or more methods with the same name but different parameter lists.

Calculator.java
class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }
}

Both are named add, but their signatures differ: add(int, int) vs. add(int, int, int).

Why bother?

Without overloading we'd need separate names for essentially the same operation — addTwo(), addThree(). With overloading, one meaningful name covers several versions of the same general operation, and Java picks the right one from the arguments.

Analogy — ordering a pizza 🍕

The basic action is always "Order Pizza" — but you might supply just that, or add a size, or a size and toppings. orderPizza(); orderPizza("Large"); orderPizza("Large", "Cheese"); — same name, different information.

02

Basic syntax, and the key rule

Java
void display() {
    System.out.println("Hello");
}

void display(String name) {
    System.out.println("Hello " + name);
}
⭐ The key rule

The overloaded methods must have different parameter lists. The list can differ by: 1) number of parameters, 2) data types of parameters, or 3) order of parameter types.

03

Overloading by number of parameters

Java

    System.out.println("No information");
}

    System.out.println("Name: " + name);
}

void display(String name, int age) {

    System.out.println("Age: " + age);

Java chooses based on the arguments supplied.

04

Overloading by data type

Java
void show(int number) {
    System.out.println("Integer: " + number);
}

void show(double number) {
    System.out.println("Double: " + number);
}

show(10);     // → show(int)
show(10.5);   // → show(double)
Analogy — different plug types

The action is still "connect," but the plug type tells the system which connection process is appropriate. Similarly, the parameter type helps Java select the overloaded method.

05

Overloading by parameter order

Even with the same parameter types, a different order creates a valid overload.

Java
void display(String name, int age) {
    System.out.println("Name first");
}

void display(int age, String name) {
    System.out.println("Age first");
}
display("Anu", 20) → matches display(String, int) display(20, "Anu") → matches display(int, String)

The order gives Java enough information to tell the two apart.

Greetings

Analogy — a search bar 🔎

You might search by product name, or name + category, or name + category + price range. The basic action is always Search. search(String), search(String, String), search(String, String, double) — different inputs, same general operation.

08

Constructor overloading

Constructor overloading means having multiple constructors in the same class with the same class name, but different parameter lists.

Student.java
class Student {

    String name;
    int age;

    Student() {
        name = "Unknown";
        age = 0;
    }

    Student(String studentName) {
        name = studentName;
        age = 0;
    }

    Student(String studentName, int studentAge) {
        name = studentName;
        age = studentAge;
    }
}

Three overloaded constructors: Student(), Student(String), Student(String, int).

Why use it?

Not every object has the same amount of information available at creation time. Constructor overloading gives different ways to create the object depending on what's known:

Java
Student student1 = new Student();
Student student2 = new Student("Anu");
Student student3 = new Student("Rahul", 21);
Analogy — hotel check-in 🏨

Sometimes the hotel already has your name, age, and room preference. Sometimes just your name. Sometimes it's a temporary booking with nothing yet. The hotel can still start the process with whatever's available — constructor overloading gives the same flexibility.

Constructor overloading by type and by order

By data type
class Product {
    String name;
    int code;

    Product(String productName) {
        name = productName;
        code = 0;
    }

    Product(int productCode) {
        name = "Unknown";
        code = productCode;
    }
}
By parameter order
class Student {
    String name;
    int age;

    Student(String studentName, int studentAge) {
        name = studentName;
        age = studentAge;
    }

    Student(int studentAge, String studentName) {
        name = studentName;
        age = studentAge;
    }
}

Product(String) vs. Product(int), and Student(String, int) vs. Student(int, String) — both valid, for the same reasons overloaded methods can differ.

1 — Same class nameEvery constructor uses the class's exact name.

Analogy — a restaurant menu

Method overloading is one action, order(), that accepts different requests: order(), order("Pizza"), order("Pizza", "Large"). Constructor overloading is creating a customer order in different ways depending on what information is available: Order(), Order("Pizza"), Order("Pizza", "Large").

13

Overloading is compile-time polymorphism

Don't let the term intimidate you — it just means Java determines which overloaded version to use based on the call and its arguments, before the program even runs.

Java
void print(int number) { System.out.println("Integer"); }
void print(String text) { System.out.println("String"); }

print(10);       // → print(int)
print("Hello");  // → print(String)

Remember

Both mistakes above produce the exact same signature — display(int) and calculate() respectively — so the compiler sees them as duplicate declarations, not overloads.

15

Complete examples

Calculator.java
class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }

    double add(double a, double b) {
        return a + b;
    }
}

int result1 = add(10, 20);        // → 30
int result2 = add(10, 20, 30);    // → 60
double result3 = add(10.5, 20.5); // → 31.0
Student.java
class Student {
    String name;
    int age;
    double marks;

    Student() { name = "Unknown"; age = 0; marks = 0.0; }
    Student(String studentName) { name = studentName; age = 0; marks = 0.0; }
    Student(String studentName, int studentAge) { name = studentName; age = studentAge; marks = 0.0; }
    Student(String studentName, int studentAge, double studentMarks) {
        name = studentName; age = studentAge; marks = studentMarks;
    }
}

Student student1 = new Student();
Student student2 = new Student("Anu");
Student student3 = new Student("Rahul", 21);
Student student4 = new Student("Priya", 20, 91.5);
Design benefit

Without overloading: calculateAreaOfSquare(5), calculateAreaOfRectangle(10, 5). With overloading: calculateArea(5), calculateArea(10, 5) — one memorable name for related operations. But don't overdo it: five near-identical overloads of the same method can get confusing. Ask whether each version is a sensible variation of the same operation.
