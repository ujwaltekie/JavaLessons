Chapter — Java Instance Variables and Constructors

Giving every object its own data, and setting it up the moment it's born.

When we create an object in Java, it usually needs to store information about itself.

A Student object might need to store a name, an age, and marks. These live in instance variables. A constructor is then used the moment the object is created, to give those instance variables their initial values.

Object is created ↓ Constructor runs ↓ Instance variables get their values ↓ Object is ready to use
01

What are instance variables?

An instance variable is a variable that belongs to an object — declared inside a class, but outside its methods and constructors.

Student.java
class Student {

    String name;
    int age;
    double marks;
}

name, age, and marks are instance variables. Each Student object can have its own values for these.

Why "instance" variables?

An object created from a class is called an instance of that class. Each instance has its own copy of the instance variables:

student1
name = "Anu"
age = 20
marks = 85.5
student2
name = "Rahul"
age = 21
marks = 91.0
Analogy — a student registration form 📝

The form's blank fields (Name, Age, Marks) are like instance variables — the class design. Each completed form is a different object, with its own filled-in values.

Easy way to remember

Class = blueprint. Object = the actual thing built from the blueprint. Instance variables = information stored inside each actual object.

02

Declaring instance variables

The general pattern is class ClassName { dataType variableName; }.

Java
class Car {

    String brand;
    String model;
    int year;
}

class BankAccount {

    String accountHolder;
    double balance;
}

A BankAccount object can then store accountHolder → "Anu", balance → 5000.0, and so on for each account.

03

Instance variables vs. local variables

Instance variable

class Student { String name; // here }

Local variable

void displayStudent() { String message = "Hi"; // here }
Instance variableLocal variable
Declared inside the classDeclared inside a method/block
Belongs to an objectBelongs to the method/block execution
Usable across the object's instance methodsAvailable only within its own scope
Each object has its own stateCreated fresh for the local execution
Common mistake

Don't assume every variable written inside a class is an instance variable — one declared inside a method body, like String message = "Hello"; inside display(), is a local variable, not an instance variable.

04

What happens when we create an object?

If we haven't assigned values ourselves, Java gives instance variables default values: String → null, int → 0, double → 0.0, boolean → false.

Java
Student student1 = new Student();
// student1.name = null
// student1.age  = 0

student1.name = "Anu";
student1.age = 20;

This works, but there's a more organised way to set up a new object from the start: constructors.

05

What is a constructor?

A constructor is a special member of a class that runs when an object is created — its job is to initialise the object.

Java
class Student {

    String name;
    int age;

    Student(String studentName, int studentAge) {
        name = studentName;
        age = studentAge;
    }
}

Student student1 = new Student("Anu", 20);
// name = "Anu", age = 20 — set immediately
Analogy — filling out a registration form

Rather than creating a blank record and filling in the name and age afterwards, you provide the information during registration itself: new Student("Anu", 20). Think of a constructor as the object's initial setup process.

06

Constructor syntax, and Rule 1: same name as the class

A constructor's name must be exactly the class name — including capitalization.

class Student { Student(String studentName, int studentAge) { name = studentName; age = studentAge; } }

Correct

class Student { Student() { ... } }

Incorrect

class Student { student() { ... } }
Remember

Java is case-sensitive. Class name = Constructor name, including capitalization.

07

Rule 2: a constructor has no return type

Constructor

Student() { System.out.println("Created"); }

Method (not a constructor!)

void Student() { System.out.println("Created"); }

Adding void turns it into a regular method that happens to share the class's name — not a constructor.

Memory trick

Constructor = same class name + NO return type.

08

Rule 3: it runs when an object is created

Java
class Student {
    Student() {
        System.out.println("Constructor executed");
    }
}

Student student1 = new Student();   // prints once
Student student2 = new Student();   // prints again

Each object creation triggers the constructor. For a parameterised constructor, the flow behind new Student("Anu", 20) is:

new Student("Anu", 20) ↓ Create object ↓ Call constructor ↓ Student(String studentName, int studentAge) ↓ Initialise instance variables
09

Constructors with and without parameters

No parameters
class Student {
    String name;
    int age;

    Student() {
        name = "Unknown";
        age = 0;
    }
}
With parameters
class Student {
    String name;
    int age;

    Student(String studentName, int studentAge) {
        name = studentName;
        age = studentAge;
    }
}

Following the process step by step

For Student student1 = new Student("Anu", 20);:

1. Object created: name = null, age = 0 2. Constructor receives: studentName="Anu", studentAge=20 3. Constructor assigns: name = studentName; age = studentAge; 4. Object initialised: name = "Anu", age = 20
Analogy — setting up a new phone

The phone exists, but the setup process (name, language, region) gives it its initial configuration. A constructor performs a similar initial setup for an object.

10

Multiple objects, different values

One constructor can initialise many different objects.

Java
Student student1 = new Student("Anu", 20);
Student student2 = new Student("Rahul", 21);
Student student3 = new Student("Priya", 19);
student1
name = Anu
age = 20
student2
name = Rahul
age = 21
student3
name = Priya
age = 19

Without a constructor, we'd create the object, then assign each field by hand. With a constructor, creation and initialisation happen together:

Without constructor

Create object → Assign name → Assign age → Object ready

With constructor

Create + initialise → Object ready
Main purpose of a constructor

To make sure an object starts with an appropriate initial state.

11

Constructor vs. normal method

ConstructorNormal method
Initialises an objectPerforms an operation/task
Same name as classCan have its own descriptive name
Has no return typeHas a return type, including void
Runs when an object is createdRuns when explicitly called
Used for initial setupUsed for behaviour/operations

A constructor is invoked as part of object creation; a method is called explicitly on an existing object:

Constructor: new Student() → creation + initialisation Method: student1.displayStudent() → perform an operation
Analogy — building a house 🏠

The constructor is the house's initial setup — rooms, doors, windows, structure. Methods are things you do with the finished house: openDoor(), turnOnLights(), lockDoor(). Constructor → "Set me up." Method → "Do something for me."

12

A complete constructor example

Car.java
class Car {

    String brand;
    int year;

    Car(String carBrand, int carYear) {
        brand = carBrand;
        year = carYear;
    }

    void displayCar() {
        System.out.println("Brand: " + brand);
        System.out.println("Year: " + year);
    }
}

Car car1 = new Car("Toyota", 2025);
car1.displayCar();
Output: Brand: Toyota Year: 2025

Two different jobs: the constructor initialises car1; the method displays its information.

13

Constructor parameters are formal parameters

Constructor parameters work exactly like method parameters — the same input/output thinking applies.

Java
Student(String studentName, int studentAge) {
    name = studentName;
    age = studentAge;
}

Student student1 = new Student("Anu", 20);
CONSTRUCTOR ↑ │ "Anu", 20 ← actual arguments │ ↓ Initialise object
14

If we don't write a constructor

If a class declares no constructor, Java provides a default constructor, so new Student() still works — instance variables get their normal default values.

Java
class Student {
    String name;
    int age;
}

Student student1 = new Student();   // works: name=null, age=0

But the moment you write your own constructor, Java stops providing that default one:

Java
class Student {
    String name;

    Student(String studentName) {
        name = studentName;
    }
}

Student student1 = new Student("Anu");   // OK
Student student2 = new Student();        // no longer works!

If you want both forms, define both — one idea that leads directly into constructor overloading:

Java
class Student {
    String name;

    Student() {
        name = "Unknown";
    }

    Student(String studentName) {
        name = studentName;
    }
}
Important

The compiler-provided default constructor is available only when you haven't declared a constructor yourself.

15

Initialising multiple variables

Java
class Laptop {

    String brand;
    String model;
    int price;

    Laptop(String laptopBrand, String laptopModel, int laptopPrice) {
        brand = laptopBrand;
        model = laptopModel;
        price = laptopPrice;
    }
}

Laptop laptop1 = new Laptop("Dell", "Inspiron", 60000);
// brand = "Dell", model = "Inspiron", price = 60000
16

The this keyword

this refers to the current object. It's especially useful when a parameter name is the same as the instance variable it initialises.

Java
class Student {

    String name;
    int age;

    Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
this.name → instance variable name → constructor parameter this.age → instance variable age → constructor parameter

this.name = name; means: "Take the name parameter and store it in the current object's name variable."

Analogy — your own locker 🔐

If someone says "put this book in my locker," "my locker" identifies the current person's locker. In Java, this.name means "the name belonging to this current object." For student1, this refers to student1; for student2, it refers to student2.

Without this

Student(String studentName) { name = studentName; }

With this

Student(String name) { this.name = name; }
Teaching tip

Using different parameter names is often easier when first learning constructors. Once comfortable, this is extremely common in Java code.

17

Constructor and object state

The values stored in an object's instance variables are its state. Same class, different objects, different state:

Java
Car car1 = new Car("Toyota", 80);   // brand=Toyota, speed=80
Car car2 = new Car("Honda", 60);    // brand=Honda,  speed=60
Key concept

Instance variables describe the object's data/state. Constructors establish the object's initial state.

Constructor + method, together

Java
class Student {
    String name;
    int age;

    Student(String studentName, int studentAge) {
        name = studentName;
        age = studentAge;
    }

    void displayDetails() {
        System.out.println("Name: " + name);
        System.out.println("Age: " + age);
    }
}

Student student1 = new Student("Anu", 20);
student1.displayDetails();
Object creation → Constructor → Initialise data → Object ready → Methods can perform tasks
18

Constructor checklist

  • Does its name exactly match the class name?
  • Does it have no return type?
  • Does it initialise the required instance variables?
  • Are its parameters the correct types?
  • Are the values assigned correctly?
  • If using this, is it clear which name refers to the object and which to the parameter?
Java
class Product {
    String name;
    int price;

    Product(String productName, int productPrice) {
        name = productName;
        price = productPrice;
    }
}

Find the problem Is this constructor valid?
Java

    String name;

        System.out.println("Employee created");

Yes, it's syntactically valid — but it never assigns name, so the instance variable stays null. If the intent is to store the name, it should read name = employeeName;
